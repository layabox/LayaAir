# JS library regression checks

## Standalone bytecode check

```sh
npm run check:js-bytecode
```

This separately checks the fixed Box2D and PhysX targets. `npm run build` does not run it. Pass explicit source files after `--` to select libraries, or set `JS_BYTECODE_NODE` to the target Node/Electron executable. The check only warns and never rewrites source.

## Recast

The engine ships the JS/WASM artifacts from [layabox/recastnavigation](https://github.com/layabox/recastnavigation), commit `72cbb77`, on official upstream `9f4ce64458dfae86e1239c525ddc219c4e9e06f1`. Update all three `recast-navigation.js`, `recast-navigation-wasm.js` and `recast-navigation-wasm.wasm` files together. Build instructions, the 50 KiB bytecode gate, optimization verification and full API/slope/obstacle/loading tests live in the fork's `laya/` directory. The engine bytecode checker no longer has Recast targets.

These artifacts enforce maximum slope and use official native layers with area-type boundaries. Those are intentional changes from the previous engine binary.

Run from the engine repository:

```sh
node tests/physics/recast-regression.cjs
node tests/physics/recast-regression.cjs /path/to/recast-navigation.js /path/to/baseline-result.json
node tests/physics/recast-regression.cjs /path/to/recast-navigation.js --build-benchmark
```

Use `ELECTRON_RUN_AS_NODE=1 /path/to/Electron` in place of `node` to test the actual IDE V8 runtime. Redirect stdout to a JSON file to capture a complete baseline; stderr contains failures.

The default fixture is the fork's independent official native-layer reference, captured from unmodified upstream algorithms on the 2024 source snapshot. Its provenance and source SHA-256 are stored in the fixture. Failed nearest-poly queries leave coordinates uninitialized; only those coordinates are normalized, matching the fork tests. Each case compares exact Float32 position/velocity bytes across all 480 frames, every active agent's state/target state/reference, query outputs, command results, diagnostic messages, and checkpoints. Timing is excluded. The fixture is not regenerated by the build or by the test.

Cases cover a plane, multiple tiles, an obstacle, watershed/monotone/layer partitioning, a disconnected mesh, an off-mesh link, and a shallow ramp. Crowd uses 24 agents with avoidance/separation, variable and zero time steps, velocity requests, target changes, agent removal/re-addition, and parameter changes. Assertions require actual movement and off-mesh traversal. Tile removal/rebuilding and area/exclusion filters are exercised too. Only the initialized `nsteerPath` points are compared, and borrowed heap views are copied before further native calls.

`--build-benchmark` warms up 20 tile rebuilds and measures 100 per case. It records a query hash after every rebuild. It does not use the default Crowd fixture; pass a captured benchmark JSON as the second positional argument to require identical query hashes. Run baseline and candidate sequentially without other CPU-heavy tasks for useful timing comparisons.

For performance conclusions, use the fork's `laya/tests/performance.cjs` paired benchmark. Both engine and fork regression scripts now seed randomness inside each VM while retaining that VM's native Math intrinsics. Earlier measurements made by injecting the host Math object produced misleading JS slowdowns and are superseded by the fork's validation record. The paired benchmark also caches agent handles, yields between frames, and excludes queries/hashes from API timers.

Future Recast updates must pass the fork's build gate and regressions before importing the paired artifacts here. This engine suite keeps its existing path/Crowd checks without duplicating the fork's build tools.

## Bullet and PhysX

```sh
node tests/physics/bullet-regression.cjs
node tests/physics/physx-regression.cjs
```

Both scripts accept `[source.js] [baseline-result.json]`, support Electron's `ELECTRON_RUN_AS_NODE=1` mode, and default to a checked-in compact fixture captured from the unmodified source (identified by SHA-256). Fixtures are never regenerated by builds. The complete behavior digest excludes timing and coverage counters. IEEE negative zero is encoded explicitly in JSON, and body state is also hashed as exact Float64 bytes.

Bullet runs three scenes for 360 steps each: mixed primitives, convex hull contacts, and a fixed joint with constraint debug drawing. It compares every frame's transforms, velocities and activation states; ordered contact positions, normals and separations; and motion/debug callback order. A test-only in-memory shim captures the actual line coordinates and colors passed to the debug import, whose normal implementation logs only the call name. Contact count and actual motion must be nonzero.

PhysX runs eight scenes for 360 steps each: mixed primitives and convex hulls with both legacy and PCM contact generation, convex CCD, height fields, triangle meshes, and a capsule controller over a mesh. It also exercises triggers, impulses/velocities, kinematic targets and switching back to dynamic motion, actor removal/re-addition, rays and four geometry sweeps. Collision masks are explicitly configured, PCM flags are checked numerically, and tests require contact callbacks with actual contact points. Event vectors are snapshotted immediately; only the initialized contact points exposed by the binding are compared (up to four). Query and event getter fields are copied into plain values.

Set `PHYSICS_COVERAGE=1` to instrument only fixed entries in an in-memory source copy and report invocation counts. These scenes exercise Bullet's modified constraint-debug entry and unchanged convex-contact control path and PhysX's `bda`, `lM`, `ZL`, `qF`, and `CX`. The other PhysX size-risk kernels remain explicit bytecode targets with every extracted helper; this suite does not claim execution of every geometry or solver branch. Performance comparisons should use instrumentation disabled and run the original and candidate sequentially.
